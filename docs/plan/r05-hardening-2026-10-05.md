## Single-session context decision

An existing active session is pinned to its authoritative directory; catalog discovery for its mutations must use that directory, not a newly chosen folder. The chosen folder scopes root browsing/new creation. Loading/creating a different session switches the catalog context. Merely choosing a folder must not move an existing backend session, discard an unresolved mutation, or imply it stopped. Display the session/catalog directory explicitly. This is a P1 invariant, not Phase-4 project navigation.

The pinned v2.0.20 OpenAPI was re-read from commit `84c9be93a56304a108f1a22df0c5d62c26d5b6ca`: session list accepts `directory`, `project`, `subpath` filters (not `location[directory]`), roots use `parentID=null`; cursors are opaque. The pinned session handler passes first-page query into `session.list` and restores query scope from a supplied cursor. The pinned `packages/core/src/session/store.ts` list implementation applies **exact directory equality**, not recursive-prefix matching; project/subpath is a separate query mode. P1 browsing will use directory alone with the root filter. No cross-resource ordering or replay is inferred.
